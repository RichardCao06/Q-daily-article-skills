# Research Rules

Use these rules when collecting entities, source links, and updates.

## 1. Rank by Signal

Do not rank by fame alone.

Prefer entities that:
- generate first-party information regularly
- influence the direction of the field
- ship products, research, or policy signals
- affect adjacent ecosystems

## 2. Label Source Quality

Every source should be treated as one of:
- `official`
- `community`
- `media`
- `aggregator`

Do not collapse these into one bucket.

## 3. Use Exact Dates

When tracking updates:
- store exact publication dates
- define the collection window explicitly
- never rely on phrases like `recently` or `last week` without concrete dates

## 4. Prioritize First-Party Sources

Default order:
1. official site
2. official blog or newsroom
3. official social account
4. official docs or changelog
5. official video channel

Only use media coverage if:
- the user requested it
- or the first-party source is unavailable

If using media, say so clearly.

## 5. Do Not Invent Missing Updates

If a tracked entity has no reliable update in the time window:
- store nothing
- or record the coverage gap separately

Do not create placeholder content that looks like a real update.

## 6. Preserve Attribution

Every structured item should retain:
- the original URL
- who published it
- when it was published
- why it belongs to the tracked entity

## 7. Separate Entity Types

A person, company, and product often need different source strategies.

Typical priorities:

### Person
- official X
- personal website or blog
- institution page
- official interviews

### Company
- website
- newsroom
- blog
- docs
- official social channels

### Product
- product page
- changelog
- docs
- release notes
- parent company announcements

## 8. Prefer Traceable Summaries

Summaries should be short and factual.

Each one should answer:
- what happened
- why it matters
- where the source is

If a summary cannot be traced back to a source, do not store it.
